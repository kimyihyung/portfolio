Shift or rescale — they are not the same

A shift adds the same number of seconds to every cue: the file is uniformly early or late. A rescale multiplies the timeline, which is what a frame-rate mismatch needs — 23.976 fps played at 25 runs fast by 4.3%, barely anything in the first minute and over a minute an hour in. Shift first, then look at the last cue; if the error grows, rescale instead.

Reading speed beats line length

A cue is judged by characters per second, not by how many lines it has: 15–20 CPS reads comfortably, above 25 is a strain however short the cue. That is why a two-word cue held for 0.4 s gets flagged just like a long one.

Two lines, and a break where the sentence breaks

Line breaks belong at a clause boundary, not in the middle of a phrase. The break here is greedy on a width budget where CJK characters count double — it keeps the pair balanced to within a character or two, then you can nudge the break in the source.

What each format keeps

SRT carries numbers, times and text; VTT adds a header, cue identifiers and settings after the time; ASS carries a script header, a style and comma-separated fields. Converting down to VTT or SBV drops styling on purpose, and coming back up writes a clean default style rather than the original one.

1.0 s is the shortest a cue should stay on screen; 5–6 s is a comfortable ceiling.

Questions that come up

Is my subtitle file uploaded?

No. The file is read with the browser's own file API or pasted into the box, parsed in the tab and written back out there. The page makes no network request, so the dialogue never leaves the device.

Will the conversion keep the styling?

SRT and VTT carry italic and bold tags, which survive. A full ASS style table does not: converting to SRT or VTT keeps the text and the times and drops the styling, and going back to ASS writes one clean default style.

Why is my file detected as the wrong format?

Detection looks at the first lines: a WEBVTT header, a [Script Info] block, numbered blocks with --> and commas, or a bare time pair. A file that starts with a title card instead of a cue can be read as the wrong one — pick the format in the list and it is parsed as that.
