    What actually happens to a file

    measured, not estimated

    01Decode once, then draw

    Each file is decoded by your browser's own image decoder and drawn onto a canvas at the size you asked for. If a maximum side is set, the scale is min(1, maxW ÷ width, maxH ÷ height) — the smaller of the two — so nothing is ever stretched, and a file already inside the limit is left at its own pixels.

    02The format decides the ceiling

    WebP usually wins on photos and keeps alpha. JPEG is the most compatible and the smallest for a low-detail shot, but it has no alpha, so transparency is painted over with your background colour. PNG is lossless: great for flat graphics and screenshots, and it will often make a photo larger — the table says so instead of hiding it.

    03Sizes are byte counts

    The new size under each file is the length of the encoded blob, and the totals are the sums of those blobs. Move the quality slider one notch and every file is re-encoded and re-measured, which is why the saving percentage settles where it does rather than being estimated from a formula.

    Questions

    batch · format · zip
    How much smaller will my photos get?
    It depends on where you start. A phone JPEG re-encoded to WebP at 80 usually lands at 25–60% of the original. A screenshot PNG saved as WebP at 80 often drops by 80% or more. A photo saved as PNG usually grows, because PNG stores every pixel losslessly. The numbers on this page are measured per file as you change the settings — that is the whole point of the table.
    Which format should I pick?
    WebP for anything on the web, and for logos that need transparency. JPEG when a service only accepts jpg, or when you want the smallest file from a detailed photo. PNG for screenshots, line art and flat colour where a single pixel matters — or when you need to keep transparency and WebP is not accepted.
    Why did my file get bigger?
    Because the target format stores more than the source did. PNG is lossless, so a JPEG photo converted to PNG grows several times over. Quality 100 on WebP can also exceed a modest JPEG. Look at the red +% in the row and switch the format — the same image at WebP 80 is usually a fraction of both.
    Is the ZIP built by a library or a server?
    Neither. A small store-only ZIP writer in this page builds the archive: per-file local headers, CRC32 checksums over the encoded bytes, a central directory and the end record. Store-only means no second compression pass — the images are already compressed, and deflating a JPEG again only costs time. Any unzip tool opens the result.
