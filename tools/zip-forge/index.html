What is written

Zip layout

Local header 0x04034b50 · data · central directory 0x02014b50 · EOCD 0x06054b50. The flag bit 11 is set so every name is read as UTF-8.

The checksum

CRC32 with the reflected polynomial 0xEDB88320, computed byte by byte in the tab — the value an unzip will verify before it trusts the entry.

The compression

Deflate through CompressionStream('deflate-raw'). If the browser has no such stream the entry is stored (method 0) and the .zip still opens everywhere — the panel tells you which one it used.

Left on the device

The archive exists as a blob in memory until you save it. No cookie, no storage key, no upload, no log — close the tab and nothing of yours is left behind.

Honest limits

Archives over 4 GB, Zip64, multi-part and password-protected entries are reported, not opened. A stored-heavy archive of photos will barely shrink — JPEG and MP4 are already compressed. Deflate at the browser default level is a normal ZIP, not a 7-Zip LZMA one.

What actually happens

no server in the loop

01Read, never send

Choosing a file gives the page a File object, not an upload. It is read into an ArrayBuffer with the File API, and that buffer is all the page ever handles.

02Pack

Each entry gets its CRC32, then a Deflate attempt; the shorter of the two wins. Local headers, the central directory and the EOCD are assembled into one blob and offered as a download.

03Unpack

Opening an archive means finding the EOCD from the end of the file, walking the central directory, and slicing each entry out by its offset. Deflate entries go back through DecompressionStream.

04Preview without extracting

An image becomes a blob URL the page draws; a text file is decoded as UTF-8 and shown in a pre block. Nothing is written to disk until you press download.

Questions people actually ask

five answers
Is this a real .zip, or only this page can read it?
A real one. Local file headers, the compressed bytes, a central directory and the EOCD — the same four parts every archiver writes. Windows Explorer, macOS Archive Utility, 7-Zip and unzip open the download without a warning.
What if the browser has no deflate-raw?
The archive is still valid, just bigger: entries are stored and the method byte says 0 instead of 8. The result panel names the method, so the number you see is the one you got.
Can it open a .zip with Korean filenames?
Yes. A name is decoded as UTF-8 when the UTF-8 flag is set; when it is not, the page tries UTF-8 first and falls back to EUC-KR, which is what Korean Windows archivers wrote for years. A name that survives neither is shown as bytes rather than silently mangled.
Is anything uploaded, cached or logged?
No. One HTML file, no fetch, no XHR, no WebSocket, no analytics, no external font or stylesheet. The footer counts outbound requests and keeps the number it sees, which is zero.
Will my photos get smaller?
Barely. A JPEG, MP4, PNG or PDF has already had its redundancy squeezed out, so Deflate usually returns it a few percent larger and the page then stores it unchanged. Text, JSON, CSV, SVG, logs and source code are where a .zip earns its keep.
