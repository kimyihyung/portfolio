How it works

Three things worth knowing

01 One canvas, start to finish

The file is decoded by the browser and drawn into a canvas in this tab. The frame, the backdrop, the shadow and the PNG are all produced by that same canvas, so no pixel is ever sent anywhere to be processed.

02 Frames drawn, not borrowed

The window bar, traffic lights, address pill, device bezel and dynamic island are geometry drawn in code — no system artwork, no logo, no image asset. That is why the page still makes zero external requests with three frames and nine backdrops loaded.

03 2× is the one to keep

The layout is identical at 1× and 2×; only the pixel grid doubles. Export at 2× for slide decks, retina screens and social previews, and at 1× when you need the exact pixel size of a page or a card.

Questions

Straight answers
Does my screenshot get uploaded?
No. The file is decoded by the browser's own image decoder and drawn into a canvas in this tab. The page has no upload endpoint at all — the counters in the header and the footer read the page's own network activity and stay at zero.
Which frame should I use?
macOS for dashboards, editors and developer tools, where the window says “this is a desktop product”. iPhone for a mobile screen, so the app appears in its own device. Minimal when the capture already carries its own chrome, or when the image has to fill a slide edge to edge.
Why export at 2×?
A 2× export doubles the pixel dimensions and keeps the layout identical, so text and edges stay sharp on retina displays, in presentations and in link previews. Use 1× when the destination is a fixed-size banner or a small thumbnail where the extra pixels are wasted.
Can I use the result commercially?
Yes. There is no watermark and no claim over your screenshot or the exported PNG. The device shapes are simple geometry without Apple logos or system artwork.
